The foundation is worth keeping

Scribe already uses SwiftUI, local WhisperKit transcription, FluidAudio speaker analysis, separate microphone and system audio, and a local folder for each recording. Search, transcript editing, timestamped notes, exports, calendar integration, and model management already exist. A rewrite would discard useful work.

Your microphone should always map to your identity. The app or browser audio should be analyzed for remote speakers. The main gaps are remote-speaker attribution, saved app shortcuts, visible failure handling, and a shared media timeline.

Fix these first

1. Recording failures can look like successful capture

Microphone and system-audio write failures only reach diagnostics. Manifest save failures also remain in logs. The UI can keep showing a timer and waveform. An active recording can even be deleted from the sidebar while the recorders continue running.

Report source health and successful writes, persist the recovery manifest before capture, recover orphaned audio folders, and route active deletion through stop-and-discard. Add graceful quit handling before introducing video finalization.

Evidence: MicRecorder.swift:276; SystemAudioTap.swift:153; LibraryStore.swift:96; ContentView.swift:392; RecordingSession.swift:190 and 283; ScribeApp.swift:261.

2. Speaker changes inside a sentence cannot survive the current mapping

Scribe assigns one speaker to each whole Whisper segment. It picks the single diarization interval with the greatest overlap. A short interruption can receive the preceding person's name even when the diarizer found the change.

Preserve word timestamps, match words to speaker turns, and group the result into readable paragraphs. Mark ambiguous boundaries. Changing the speech model alone will not repair this mapping.

Evidence: SpeakerDiarizer.swift:54; Transcriber.swift:77 and 130; Models.swift:21. Pinned WhisperKit defaults disable word timestamps.

3. Detect remote speakers and keep your identity fixed

The pinned diarizer defaults remove turns shorter than one second and produce exclusive speaker segments. Brief replies from Zoom, Teams, Meet, and Slack participants can be affected. Evaluate shorter turn thresholds, optional expected remote-speaker counts, and overlap handling against annotated audio.

For your stated setup, skipping speaker analysis on the microphone is correct. Label it "Nikhil (Me)" and run detection on the selected app's audio. A room-microphone mode is outside the first release. Include speakerphone echo in testing so remote voices leaking into your microphone do not become duplicate speech attributed to you.

Evidence: SpeakerDiarizer.swift:27; TranscriptionQueue.swift:125; FluidAudio 0.15.5 OfflineDiarizerTypes.swift and OfflineReconstruction.swift. These are confirmed configuration effects; their impact on your calls is unmeasured.

4. Correcting one meeting can rename a saved voice profile

If Bob is incorrectly recognized as Alice, renaming that speaker to Bob can rename or merge Alice's global voice profile. Separate a correction in this recording from editing a saved person's identity.

Store stable speaker identifiers separately from names. First support choosing a saved name and merging duplicate remote labels within the recording. Automatic name recognition is optional later work. Choosing a name or merging labels must not rename, merge, or train global voice profiles.

Evidence: TranscriptView.swift:462; VoiceProfileStore.swift:83 and 120; TranscriptionQueue.swift:140.

5. Speaker analysis can fail silently

Automatic speaker recognition defaults to off. When enabled, a model or analysis failure is logged and the document still becomes ready. The user cannot tell whether the app found one person, skipped analysis, or failed.

Show independent audio, transcript, and speaker-analysis states. Provide model readiness, a visible warning, and "Retry speaker analysis" without replacing edited text. Preserve the original transcript and make cleanup and reprocessing reversible.

Evidence: SettingsView.swift:326; TranscriptionQueue.swift:157 and 171; ContentView.swift:385.

6. Audio tracks lack a shared clock

System audio and microphone capture start sequentially. Their timestamps are discarded, and playback inserts both files at zero. A microphone outage shortens that track instead of preserving the gap, shifting later speech against the remote side.

Use one monotonic session timeline, preserve source offsets and gaps, and apply a single pause map to audio, notes, transcript timestamps, and video. Handle output-device changes and stalled sources explicitly.

Evidence: RecordingSession.swift:154; MicRecorder.swift:211 and 398; SystemAudioTap.swift:129; Models.swift:78; PlaybackController.swift:39.

Make local operation the default

Summaries currently default to Anthropic, although no cloud summary is sent without configuration and an action. Prefer an available local provider and display the destination beside Generate Summary. Move provider keys from UserDefaults to Keychain.

Show downloaded-model readiness before going offline. Add storage estimates, backup/export of the complete recording, and recoverable deletion. Chunk long summaries by model capacity instead of sending one large prompt.

SettingsView.swift:517; SummaryService.swift:60 and 93; LibraryStore.swift:91.

Correct language detection and measure performance

The Auto-detect choice leaves WhisperKit's detection flag off. Its default prefill uses English when no language is supplied. Enable detection for multilingual models and retain the detected language.

Replace window-relative progress with stage progress. Measure cold start, processing time, memory, and correction time before choosing a larger model or another local engine.

Transcriber.swift:77 and 89; pinned WhisperKit Configurations.swift:226, TranscribeTask.swift:312, TextDecoder.swift:323.

An iOS-inspired interface, built for the Mac

Use grouped surfaces, rounded controls, a clear type hierarchy, subtle translucent navigation, and light and dark appearances. Keep a Mac sidebar and keyboard support. The MacWhisper screenshots establish useful interactions; Scribe should have its own visual design.

The dashboard keeps app shortcuts and an explicit video switch. Your microphone always maps to Nikhil (Me). Browser recording intentionally includes all audible tabs. Remote speakers get neutral labels first; assigning names is optional.

The transcript view should make duplicate labels easy to correct. Choose an existing saved person or enter a name, merge another remote label into it, and undo if needed. For a one-to-one call, combine all remote labels in one action or choose one other person before recording.

Saved shortcuts need reliable app selection

Persist the app's bundle identity and recording preferences. Resolve its current audio processes at recording time, including helper processes where needed. Never save a process ID as the permanent shortcut target. If the app is closed, offer to open it; if capture is unavailable, show that state instead of silently recording every app.

Core Audio supports tapping a selected process or group of processes. The existing global tap can be extended for app selection. On macOS 26, bundle-ID selection and process restoration are available; retain a process-resolution path for the app's macOS 15 minimum. Apple's audio tap API.

Scribe's automatic detection lists currently omit Slack and Zen Browser. Manual global recording can still capture their sound. Add these to the detection tests and use saved app targets for manual shortcuts instead of relying on a fixed conferencing-app list.

AudioProcessMonitor.swift:6 and 15; SystemAudioTap.swift:64. App bundle-ID tap availability verified in the installed CATapDescription.h.

Agreed browser scope

Record audio from the selected browser, including all audible tabs, plus your microphone. Tab isolation and browser extensions are outside the requested scope. Show the source as browser audio in the recording controls.

The video switch controls whether to save video. When enabled, use the native picker for a window or display. Resolve the current target rather than relying on a saved window identifier.

Speaker correction contract

  • Show remote labels as Speaker 1, Speaker 2, and so on. Do not present a detected label count as a verified count of people.
  • Click a speaker label to rename it or choose a saved person. Apply the label consistently to every assigned turn.
  • Merge one remote label into another, including when the destination has a saved name. Support both an explicit menu button and a right-click action.
  • Offer one action to combine all remote labels when there was only one other person. The microphone is excluded from both the source and destination of every remote merge.
  • Update transcript labels, timeline labels, search, and future exports together. Preserve all words, timestamps, and original media. A merge changes attribution, not the audio itself.
  • Provide undo and keep the original detected assignments. Corrections must survive a speaker-analysis retry unless the user chooses to replace them.
  • Keep the saved people list separate from acoustic voice models. Choosing a saved name or merging transcript labels must not alter stored voice profiles.

Before recording, an optional One other person setting can assign all remote speech to one participant without clustering. Auto remains available for calls with several participants. The first release prioritizes consistent grouping and quick corrections; automatic names can follow.

Your screenshot has Parakeet v3 selected. Scribe currently transcribes through WhisperKit. Include Parakeet in the local-engine benchmark before attributing all speed or accuracy differences to capture or interface design.

MacWhisper's documented speaker controls include renaming, merging, colors, and number-key reassignment. Those correction tools are a useful benchmark. Native screen recording fits this app

Use ScreenCaptureKit for a selected window or display, Apple's content-sharing picker for selection, and AVFoundation for recording and playback. Scribe already targets macOS 15, which supports direct file recording through SCRecordingOutput and microphone capture in ScreenCaptureKit. Apple's capture and recording API walkthrough.

Explicit selection through SCContentSharingPicker grants capture of that selection for the session and provides system recording controls. Keep automatic audio recording separate from screen selection; do not silently expand an audio session to video. Apple's picker and permission explanation.

Keep the first release focused

  • One display or one window, with optional microphone and call audio.
  • 1080p, 30 fps, SDR H.264 as a practical starting preset. Confirm text readability on Retina screens.
  • Native preview, visible recording state, pause/resume, stop, and save status.
  • Audio tracks remain available independently for transcription and correction.
  • Video playback uses the transcript's existing timestamps and notes.
  • Export video and captions. Keep recording metadata in the same library item.

Defer camera overlays, automatic zoom, a full editing timeline, HDR, and automatic screen recording.

The difficult part is continuity

A single unfinished MP4 cannot inherit the current CAF recovery promise. Use finalized video segments and an atomic manifest, or prove a fragmented-container recovery strategy through fault tests.

The installed SDK warns that updating stream configuration stops SCRecordingOutput recording. Pause, source switches, and resolution changes need deliberate handling. Prototype direct output first; use AVAssetWriter if timing control and recovery require it.

Test window closure, minimization, display removal, sleep/wake, revoked capture, output-device changes, disk pressure, and quit during finalization.

Extend the existing code

Add a focused ScreenRecorder owned by RecordingSession. Extend ScribeDocument with optional video assets and timeline metadata while preserving existing document decoding. Extend PlaybackController's AVMutableComposition and expose its player to an AVKit video view. Keep transcription reading the separate audio files.

Compare two capture paths in the prototype: existing audio plus ScreenCaptureKit video with clock mapping, or separate screen, microphone, and system outputs from one SCStream. The latter supplies a common capture clock but needs device-recovery evaluation. Do not keep duplicate audio capture paths active in the same session.

A selected window controls video, not necessarily audio. The current Core Audio tap records the whole Mac. Add an explicit app-audio choice; browser process audio can include other tabs. Neither app-level audio capture nor a video window provides one track per remote participant.

Run the same consented audio in Scribe and installed MacWhisper, retaining the microphone and remote sources. Record exact models, language settings, and speaker settings.
